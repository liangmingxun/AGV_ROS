# 开发验证与实车检查分级规范

## 1. 目的

本规范用于避免把一次性平台验收、代码回归、每轮实车安全门和正式统计重复混为
一谈。在不降低实车安全、数据可信度和论文可复现性的前提下，默认只执行能够发现
当前改动所引入回归的最小检查集。

“某次运行通过 43 项分析测试和 18 项静态测试”只表示该次改动已经获得相应回归
证据，不表示后续每次修改或每轮实车都必须重复这 61 项测试。

旧 Stage 或审计文档中的“未执行”“门关闭”等状态是对应提交时的历史快照，不能单凭
该文字要求重复已经完成且已有证据的检查。当前运行协议、当前配置、Git 提交、实验
manifest 和最新有效证据共同决定是否需要重做；涉及现场安全的每轮确认不受此条影响。

## 2. 按改动影响面选择验证

| 改动类型 | 默认必须执行 | 默认不执行 |
|---|---|---|
| 仅文档 | 人工复核改动段落、路径和命令 | 编译、ROS 测试、bag 回放 |
| Python 分析/指标 | 修改模块 `py_compile`；直接对应的 Python 测试文件 | 全工作区构建、无关 ROS 集成测试 |
| YAML/launch/shell | YAML/XML/shell 语法检查；直接对应的静态测试；改变运行行为或安全门时增加一个对应集成测试 | 未修改 C++ 包的重新编译 |
| 单个 C++ 模块 | 构建受影响包；对应 gtest；必要时一个对应 rostest | 其他包和其他实验方法的测试 |
| 消息、CMake、依赖、共享控制核心 | 构建并测试所有受影响包 | 与依赖图无关的历史包 |
| 大规模重构、合并或发布 | 完整相关包回归；必要时全工作区回归 | 无 |

满足以下任一条件时才升级到完整回归：

- 修改 `agv_msgs` 或跨包接口；
- 修改公共控制核心、时间语义、单位、命令权限或物理限幅；
- 修改 CMake、package 依赖或安装规则；
- 准备合并、发布或正式统计冻结版本；
- 定向测试暴露无法定位的跨模块问题；
- 用户明确要求完整回归。

一个检查已经通过且相关文件随后没有变化，不重复执行。若多个 rostest 并行运行时
因共享 ROS master、节点名或话题发生干扰，只串行重跑失败且与本次改动相关的用例，
不得把并发冲突当成代码缺陷，也不得因此重跑所有已通过用例。

成功测试只记录命令、测试范围和通过结论，不向对话重复输出完整编译日志；只有失败
诊断才读取和引用相关日志片段。这项约束只减少输出与 token，不减少实际验证覆盖。

## 3. bag 回归的最小集合

修改 conversion、validation 或 metrics 时，默认只使用：

1. 一份已知正常的基线 bag，证明没有误拒绝；
2. 一份与当前问题对应的失败 bag，证明能够识别故障。

转换输出写入临时目录，不改写原始实验目录。只有涉及历史 schema 兼容或正式数据
重处理时，才扩展到更多 bag。

## 4. 实车检查的执行频率

### 4.1 每个新提交执行一次

- 构建发生变化的包；
- 运行与改动直接相关的单元/静态测试；
- 控制、记录器或安全门发生变化时运行一次 fake observer 或对应 fake rostest。

同一提交已经验证并同步到三车后，不在每轮 pilot 前重复构建和 fake 测试。

### 4.2 硬件或配置变化后执行

- 轮径、轮距、反馈比例、轮速/加减速能力标定；
- 0.15 m/s 举升轮安全确认；
- 单车直线、转向、S 形和路径投影检查；
- 相机内外参、标记刚体变换、遮挡和完整路径覆盖检查；
- Stage A-D 对应的阶段验收；
- 网络设备或时间同步方案变化后的长时间稳定性检查。

若硬件、配置、相机安装和网络环境均未变化，不在每轮实验前重复这些验收。发现轮速
异常、定位跳变、结构松动或网络中断时，只重新打开涉及该子系统的检查。

### 4.3 每轮实车必须执行

- 操作者、区组和运行配置可追溯；
- 试验区清空、急停可触达、现场监护；
- 轮子落地状态和本轮工装/载荷状态正确；
- 三车 serial 节点、部署兼容性和 0.15 m/s 物理限幅正确；
- 单一命令发布权，无 `move_base` 或旧控制节点竞争；
- 时钟、相机、融合状态和 recorder 正常；
- 运行后的算法有效性、任务完成、wheel pre-limit、applied/actual、fleet scale、
  emergency 和数据完整性检查。

这些门禁优先由正式启动脚本自动完成；自动检查能够覆盖的项目不再要求人工重复执行
同义命令。

## 5. 当前 M1+R1 pilot 的最小验证

当前空载、无 Robot2 降额的 1 m、0.08 m/s M1+R1 pilot，只需要：

1. 新提交在 Robot1 完成一次相关包构建和定向测试；
2. 三车同步并重启受影响节点；
3. 若上一轮出现实际轮速异常，完成一次针对该异常的举升轮复核；
4. 执行 `run_m1_r1_serial_unloaded.sh` 自带的每轮门禁；
5. 只跑一轮 pilot，并根据自动生成结果决定是否继续。

不需要同时重跑 Robot2 降额、M2a、M4、M2b、R2-R4、轻载托盘速度阶梯、完整
Stage A-D 或所有历史 ROS 测试。

## 6. 正式统计重复不是日常检查

“调试 3 次、正式原则上 8 次、有效运行不少于 6 次”属于论文样本量和配对设计，
只在 pilot 通过且配置冻结后执行。一个明确失败的 pilot 应立即分析，不为凑调试次数
重复相同故障。正式矩阵应按小论文实际主张裁剪，并在采集前预注册；不研究的方法和
补充工况不进入当前运行计划。
