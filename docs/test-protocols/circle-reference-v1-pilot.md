# 公共参考加速度一致性：0.75/0.80 对比基线

## 问题证据

M1 20260912_144750、162249、162842 的有效低速段公共速度约
.07998 m/s，变化率平均约零，但 PathReference 发布的参考加速度
平均分别 .08324、.07967、.08147 m/s²。R1 实际使用该加速度。
分布式参考先投影各局部速度，再把速度平均值投影到公共边界；
旧节点使用局部控制加速度平均值作为公共加速度。
后者不一定是已投影公共速度的导数，造成参考接口不一致。

## 修正与隔离

新增 execution/consistent_reference_acceleration（默认 false）。
启用时，仅共享 R1 串口执行路径，用最终公共速度
（已有投影及软启动之后）的逐控制周期差分作为参考加速度。
这是参考信号差分，不是摄像头实测速度差分，不额外滤波或延迟边界。
进度仍由同一最终公共速度积分。R1/分布式参考公式不变。
fail-zero 把差分历史重置到实际零参考；恢复仍经过原有软启动。
终点零速仍由原有 terminal stop 处理。无效导数触发零速路径。

独立 reference_v1 runtime 保留纵向增益1.0，显式关闭 reconciliation。
速度.10、轮速发布上限.16、Robot2比例.75或.80、降额1.5..3.5m、
降/恢复1s、定位/电压/录包门槛均不更改。当前起步配置与正常
0.10 m/s基线一致：4.0s坡度、0.008m/s有界追赶裕量、1.2s纵向
反馈接入和0.6 early-rise。
默认接口及原 tracking_v2/reconciliation_v1 配置保持旧行为，
历史实验文件不改写。上层 M1/M2a 各自授权精确绑定新 runtime。
当前降额比较使用 --derating-0p75|--derating-0p80 配合
--reference-v1；拒绝混用其他候选、一般降额和无降额。
两种比例共用 reference-v1 运行配置，但分别绑定对应比例的评估配置、
降额授权和执行授权，结果名同时包含降额比例与 reference_v1。

M2b也可进入相同0.75/0.80场景，但它是完整的英文论文上下层方法，
不使用共享R1，因此不能开启R1专属的consistent_reference_acceleration。
入口中的--reference-v1对M2b表示“同一平台对比基线”：相同Stage-D
轮速尺度、4.0s启动坡度、状态估计、融合链路、路径和降额时窗；运行名
标记reference_v1_platform，M2b公式与下层保持不变。

轮速尺度由三车agv*_chassis.yaml加载，状态估计由
localization_camera_three_car_closed_loop.yaml加载，Robot1相机/里程计融合
由localization_fusion.yaml加载。这些是公共平台配置，节点重启后作用于
M1、M2a、M2b及正常/一般降额/0.75/0.80场景。历史bag不会被改写。

## 验证与边界

通过最终参考导数单元测试：恒速零加速度、3.2s起步、
降速/恢复符号、故障重置、非有限/无效dt拒绝。
使用实际 stepDistributedReference 复现恒定公共速度与非零局部
平均加速度并存；修正使用公共速度导数。
实际 R1 + 未辨识一维底盘敏感性模型中，注入记录的错误加速度
.08324 时低速进度 RMS 为12.20mm，改为正确零加速度后.80mm。
只用于验证错误前馈机制；不是实车改善预测，也不代替三车圆弧验证。
shell/YAML/static、正式与fake节点编译、隔离fake ROS回归已检查。
fake回归保留旧行为，修正串口数学路径由上述单元测试覆盖；
没有启动物理串口控制节点做运动集成测试。

## 实车验收

先用 M1 候选检查公共速度导数与 load_acceleration_reference 对齐，
低速进度 RMS、均值与原版比较，同时检查实际轮速峰值和校验有效性。
若有改善，再跑同版 M2a，不能把新接口 M1 与旧接口 M2a
当作严格配对结论。未满足验收前，不冻结为正式统计参数。
超调仍独立检查；该接口修正不保证实际轮速不超过发布上限。
