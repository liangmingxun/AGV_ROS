# 三车无载等边三角形起始工装

## 冻结用途

本工装只用于三车无实体托盘的低速预检。它把三个转盘中心视为一个虚拟刚体的
三个支撑点：

- Robot1：前车；
- Robot2：左后车；
- Robot3：右后车；
- 等边三角形边长：`0.30 m`；
- 虚拟载荷中心：等边三角形重心；
- 路径：`A=0.05 m`、纵向长度 `1.0 m` 的单周期正弦 S 形；
- 速度仍冻结为 `0.05 m/s`，但在第二次只读门槛通过之前不授权运动。

以后放置真实物体时，必须按物体实际接触位置重新测量
`q_tangent/q_normal`，不得把本无载工装直接当成正式载荷几何。

## 支撑几何

在路径 Frenet 坐标 `[前向切线, 左法向]` 中：

| 车辆 | 角色 | `q_tangent` (m) | `q_normal` (m) |
|---|---|---:|---:|
| Robot1 | 前 | `+0.1732050807568877` | `0` |
| Robot2 | 左后 | `-0.0866025403784439` | `+0.1500000000000000` |
| Robot3 | 右后 | `-0.0866025403784439` | `-0.1500000000000000` |

三条支撑中心边长均为 `0.30 m`，三点重心为虚拟载荷中心。

## 地面世界坐标

在空旷场地选取原点 `O=(0,0)`，以 S 形纵向方向为 `world +x`，面对
`+x` 时左侧为 `world +y`。起点路径切向角为：

```text
atan(2*pi*0.05/1.0) = 0.304395797 rad = 17.440594°
```

三个转盘中心的地面标记为：

| 车辆 | world x (m) | world y (m) | 厘米坐标 |
|---|---:|---:|---|
| Robot1 | `+0.165242534262182` | `+0.051912473169863` | `(+16.524, +5.191)` |
| Robot2 | `-0.127578787669470` | `+0.117147995871838` | `(-12.758, +11.715)` |
| Robot3 | `-0.037663746592711` | `-0.169060469041701` | `(-3.766, -16.906)` |

用三条 `30.0 cm` 边长复核标记。建议转盘中心误差不超过 `5 mm`。

## 底盘轴线中点和统一初始航向

`base_link` 是左右驱动轮轴线中点。Robot1 转盘中心位于轴中点后方
`17.83 mm`，Robot2/3 位于轴中点前方 `99.08 mm`。无载工装采用统一
初始车头方向，三车均对准 S 形起点切向
`0.304395797364615 rad = 17.440594°`：

| 车辆 | base x (m) | base y (m) | yaw (rad) | yaw (deg) |
|---|---:|---:|---:|---:|
| Robot1 | `+0.182252857360210` | `+0.057256423777858` | `0.304395797364615` | `17.440594°` |
| Robot2 | `-0.222103903348248` | `+0.087452054972220` | `0.304395797364615` | `17.440594°` |
| Robot3 | `-0.132188862271489` | `-0.198756409941319` | `0.304395797364615` | `17.440594°` |

摆车时优先让转盘轴线中心对准支撑标记，再让三个 `base_link +x` 对准同一组
平行航向线。建议航向误差不超过 `1°`。

统一初始车头只属于实物起始工装。Robot1 后置支撑点的精确前馈使用终点边界
反向积分，Robot2/3 前置支撑点使用起点边界正向积分；控制器在开始推进后允许
三车航向逐渐分开。
初始工装与严格前馈参考之间允许存在小幅航向差；第二次只读门槛只验证测得的
支撑三角形和载荷路径状态，不会把三车航向强制保持平行。

## 里程计零点

三车放置并完全静止后，各自底盘节点必须已经连接串口。先确认 raw、applied、
actual 左右轮速度均接近零，再分别调用：

```bash
rosservice call /agv1/reset_odometry
rosservice call /agv2/reset_odometry
rosservice call /agv3/reset_odometry
```

每次必须返回 `success: True`。复位后检查三车 odom 的 x、y、yaw 均接近零。
此时 `localization_odom.yaml` 中的 `world_to_odom` 就等于上表三个
`world_to_base` 起始位姿。

车辆一旦被人工移动，必须重新对准标记并重新复位里程计。

## 第二次只读门槛

保持：

```text
enable_commands=false
enable_derating=false
```

重新启动中央只读入口后运行：

```bash
rosrun multi_agv_bringup check_three_car_readonly_gate.py \
  --observe-seconds 5 \
  --require-valid-state
```

必须同时满足：

- 三车 robot、support、path 有效位均为 true；
- `load_pose_valid=true`；
- `load_path_state_valid=true`；
- 三车命令和降额话题仍无 Publisher；
- 三车静止且无控制循环超时。

即使第二次只读门槛通过，当前三个
`hardware_execution_authorized` 仍保持 false。三车运动必须使用后续独立的
有界无载入口，不得直接在通用中央入口上绕过门控。
