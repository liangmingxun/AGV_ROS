# 参数无关实验工具链使用说明

本工具链只补齐无需真实物理数值的软件能力。所有候选标定、Stage 证据和配置审批
默认 fail-closed；任何脚本都不会修改 `hardware_execution_authorized`，也不会取得
`/agvN/chassis_command` 发布权。

## 1. 相机与标记 SE(2) 标定工作区

```bash
rosrun multi_agv_analysis calibration_workspace.py init CALIB_DIR
```

填写 `calibration_policy.yaml` 中由物理协议决定的样本数和残差阈值，然后使用
`add-tag-pair` 录入三台车的标记位姿与车体位姿测量对。当前四固定码方案在线
解算 `world_T_camera`，不要求 `add-world-pair`：

```bash
rosrun multi_agv_analysis calibration_workspace.py solve \
  CALIB_DIR CALIB_DIR/calibration_candidate.yaml \
  --dynamic-ground-reference
```

`add-world-pair`/离线二维刚体对齐仅在以后需要把固定码坐标系再对齐到实验室
既有坐标系时使用，不是当前定位主链。默认 `required_entities` 只有
`agv1/agv2/agv3`；载荷会明确保留在 `unresolved_entities`，不会被伪造为已标定。

候选文件始终保持 `calibration_authorized: false` 和
`extrinsics_frozen: false`。人工复核、原始证据归档和 Stage 签字完成后，才能把数值
复制到另一个受审批的正式配置。

已有 bag 转换为 CSV 后，可生成不带授权结论的相机质量报告：

```bash
rosrun multi_agv_analysis camera_quality_report.py \
  RUN_converted camera_quality.json
```

报告统计每路频率、到达延迟、时间戳乱序/重复、长间隔、置信度分布以及
raw/filtered 接受率，始终保持 `quality_authorized: false`。

## 2. 配对批次计划

复制并填写 `paired_experiment_template.yaml`，然后：

```bash
rosrun multi_agv_analysis experiment_batch.py create SPEC.yaml PLAN.yaml
rosrun multi_agv_analysis experiment_batch.py next PLAN.yaml \
  --approval-id task18_m1_fake_rehearsal_v1
```

`next` 只打印建议命令，不执行。运行状态必须显式使用 `mark` 从
`pending → running → complete/invalid`；完成项必须登记 manifest 和 metrics。

## 3. 配对统计、表格与 SVG

```bash
rosrun multi_agv_analysis aggregate_experiment.py \
  PLAN.yaml report.json summary.md \
  --baseline M1_R1 \
  --metric wheel.demand_exceedance_time \
  --metric path.progress_rmse \
  --comparison-csv comparisons.csv \
  --plot-dir figures
```

输出包括每种方法的均值、标准差、中位数、四分位距，以及配对差值、确定性 bootstrap
95% 区间和双侧符号翻转检验。正式论文汇总应增加
`--require-formal-statistics`，任何未通过正式评价窗口的运行都会被拒绝。

## 4. Stage A–D 电子证据

```bash
rosrun multi_agv_analysis manage_stage_evidence.py init \
  evidence.yaml PROJECT_ID
rosrun multi_agv_analysis manage_stage_evidence.py attach \
  evidence.yaml stage_a FILE --label bag_and_validation
rosrun multi_agv_analysis manage_stage_evidence.py sign \
  evidence.yaml stage_a operator NAME
rosrun multi_agv_analysis manage_stage_evidence.py sign \
  evidence.yaml stage_a reviewer NAME
rosrun multi_agv_analysis manage_stage_evidence.py pass \
  evidence.yaml stage_a
rosrun multi_agv_analysis manage_stage_evidence.py audit \
  evidence.yaml evidence_audit.json
```

阶段必须按 A、B、C、D、formal 顺序通过。`candidate` 只能生成
`candidate_requires_manual_registry_review`，并强制
`formal_statistics_authorized: false`、`hardware_execution_authorized: false`。
`audit` 只有在全部阶段完整通过后才返回成功；证据结构正常但尚未完成时会明确输出
`INCOMPLETE`。

## 5. 三主机只读健康检查

离线检查清单：

```bash
rosrun multi_agv_analysis fleet_health_check.py \
  $(rospack find multi_agv_bringup)/config/fleet_inventory.yaml \
  health.json --offline
```

接入 ROS 网络后移除 `--offline`。工具检查主机角色、IP 唯一性、ROS Master、
三车状态发布权和命令权，但不使用 SSH、不改远端配置、不发运动命令。

## 6. 可选 ROS 软件监视器

```bash
roslaunch multi_agv_bringup software_watchdog.launch \
  monitoring_enabled:=true
```

它监视消息接收年龄和发布者数量，只发布：

- `/multi_agv/software_watchdog_ok`
- `/multi_agv/software_watchdog_diagnostics`

故障默认锁存到进程重启。该节点不会发布零速或底盘命令，因此只能作为 Linux/ROS
诊断证据，不能替代 STM32 看门狗、急停或断电安全。
