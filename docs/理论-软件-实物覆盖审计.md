# 理论—软件—实物覆盖审计

审计基线：`实物实验设计_v1.2.1_接口冻结版.md` 与当前平台基础分支。本文只记录仓库中可由代码或自动测试证明的状态；既往实车标定结果仍须将数值和原始记录归档后才算正式冻结。

## 当前结论

当前代码已完成实施计划 Task 0–17 可由软件完成的范围，以及 Task 18 的软件门禁接口：包括三车 ROS 平台基础层、M1/M2a/M4、R1–R4、完整 M2b、顶部视觉适配边界、记录分析链、有界正式评价窗口、配置审批注册表和 Stage A–D 签字协议。M2b 固定约束发生器与文献非线性映射已使用权威 Experiment2 程序生成的 100 步黄金向量逐字段对齐，并接入仅限 fake transport 的三车 ROS 链；运行时能力仅记录，不进入 M2b 控制方程，最终仍经过相同物理能力限幅器。

当前代码仍不能开展正式实验 1、2a、2b、3，也不能声称论文完整系统已经实物验证。所有正式算法 YAML 的硬件执行门仍为 false，代码仍无正式算法串口入口；审批注册表中的条目均为 `software_rehearsal_only` 且明确拒绝正式统计。真实相机内外参、标记到三车/载荷的刚体变换、置信度语义、延迟与遮挡阈值尚未冻结，载荷标定接口保留但未放行。Task 18 文档是待执行检查表，不是已经通过的物理证据。

软件收尾进一步补齐了三项审计缺口：M2b 的文献通道输入限制已与运行时能力报告隔离，实时能力只记录并留给统一车端物理限幅；记录器在 rosbag 完成全部订阅后发布带方法标识的 5 Hz armed 心跳，算法可在录包未就绪、记录器意外退出或方法不匹配时保持零输出；分析链已覆盖支撑点/载荷/刚体残差、能力衔接、分类型限幅、R1 内部量和 M2b 分散度。以上仍不构成硬件或正式统计授权。

本次视觉复核又关闭了坐标连续性缺口：UDP桥为每次四地码锁定生成世界坐标代次，Task 15与路径状态估计器在代次变化时同时清空滤波、速度和同步历史，拒绝退休代次迟到包；Task 17记录完整代次和位姿内嵌代次，正式校验拒绝同一运行拼接两套世界坐标。Windows四地码右手系不再允许通过翻转Y轴而把正高度翻到地面下方。上述修复保证软件不制造跨坐标系轨迹，但定位绝对精度仍必须通过独立尺检和动态轨迹验收。

## 当前代码已修正的问题

- 冻结消息测试由两个消息扩展为全部八个消息的字段精确校验。
- 话题队列与 §21.0.1 对齐：命令 1，反馈/能力/降额 5，里程计/IMU 10，均不锁存。
- 反馈和能力序列号改为每次发布递增；重复的同序列降额命令改为幂等，不再反复重启斜坡。
- 增加 `/agvX/reset_odometry`，仅在 raw、applied、actual 轮速均接近零时允许复位。
- 串口初始化增加超时，写失败不再以成功码静默退出；串口速度安全上限与上报能力保持一致。
- 串口接收按冻结的 66 字节固定帧长解析，覆盖分包、粘包、二进制载荷内伪分隔符和损坏帧恢复，避免偶发 `Invalid data size` 丢帧。
- QEKF 使用校正并滤波后的陀螺数据；非法 IMU 标定、车号和冻结坐标系在启动时直接报错。
- 支撑点偏置由硬编码改为各车 launch 参数，便于后续实测冻结。
- 雷达驱动补充 `libpcap` rosdep/CMake 检查，并修复串口关闭函数缺少返回值的问题。
- 增加局部窗口路径投影、因果差分与单极滤波；不收敛、过大残差、乱序时间戳和异常时间间隔均显式无效。
- 三车 odom 状态按车独立新鲜度发布；单车掉线不会伪造该车状态，三点不同步或刚体残差超限时不伪造托盘状态。
- 能力映射分别处理左右轮及加/减速度，公共能力取三车最小，同一加速度预留不重复扣减。
- 二维支撑跟踪器按同一载荷弧长生成三车不同轮速需求；fake 端到端保留 raw/applied/actual 链。
- Robot2 降额只由实际状态触发，目标不变时序列号不变；能力变化到 applied 生效的时间顺序由测试覆盖。
- fake 本机三车与 Robot1 中央实物入口已拆分，避免实物部署时在 Robot1 误启三套本地串口底盘。
- 三车运动全过程持续检查 `CooperativeState` 的单一发布权，不再只在启动门检查，避免故障/竞争状态源交替消息造成停机竞态。
- Task 13/14 已记录两份权威参考 SHA-256，生成可复现黄金 CSV；M1 上层与完整 R1 下层逐字段通过。
- 增加仅限 fake 的正式算法 ROS 入口；固定记录 90 个内部状态字段，只有核实三个实际底盘均为 fake 后才注册命令发布器，拒绝 serial/硬件授权，并在状态或能力失效时持续对三车发布零命令。
- Task 17 记录器只有在专用 rosbag 节点已订阅全部必需话题后才发布 armed 心跳和方法标识；心跳失效或方法不匹配时算法可失效置零，三车命令发布权在运行中发生任何变化都会终止记录并留下无效清单。
- 因果对齐现在显式标记 `ExperimentState` 覆盖情况；缺少正式评估窗口时仍可用于 fake 演练，但指标会标记 `formal_statistics_ready=false`，不得进入论文统计。
- Task 17 将底盘能力报告统一为 100 Hz，并以 90 Hz 作为记录验收下限；IMU、里程计、命令、反馈、能力、协同状态、路径状态与控制器状态均纳入频率审计。
- Task 15 增加不发布 TF/命令的 `pose_provider`、camera 模式状态估计、四路 raw/filtered/置信度记录和逐标记掉线测试；低置信度位姿仅保留 raw，不进入实时状态。
- Task 15 增加世界坐标代次的端到端重置语义；单码长时间失效后滤波从首个恢复样本重新初始化，避免把失效前后位置平滑成虚假轨迹。
- Task 16 增加完整 M2b 控制核、黄金 CSV、固定约束保护、能力 log-only 断言、相同物理限幅与 fake 三车 ROS 端到端。
- Task 17/18 增加按实际进度开闭的连续评价窗口、审批配置 SHA 注册表和正式统计拒绝门；缺少窗口或正式批准时校验器明确拒绝/降级。
- Task 17 相机运行额外归档Windows配置/源码清单与Robot1桥配置，并拒绝标定代次变化。
- Task 18 增加 Stage A–D 和正式实验签字协议；所有文档初始状态均为“未执行”，不会自动授权实物。

## 下一阶段唯一推荐顺序

1. 使用 `formal_fake_algorithm.launch` 或 `formal_fake_m2b.launch`、`formal_evaluation_window.launch` 与 `experiment.launch` 完成一次获批的非统计软件演练；当前 `formal_statistics_ready=false` 是预期结果。
2. 将已经完成的单车/三车预实验 bag、机器配置、日期和人工测量整理成冻结记录；补齐逐车轮径/轮距/左右比例、支撑高度、初始摆位不确定度和接受阈值，未归档的结果只算工程观察。
3. 选定并安装顶部相机，按 `test-protocols/task15-camera-software-gate.md` 实测内外参、四个标记变换、置信度、延迟、遮挡和全路径覆盖；替换占位值并冻结配置哈希。在此之前不得打开 camera 双重门，里程计结果不得作为载荷真值。
4. 按 `docs/test-protocols/stage-a-ros-chassis.md` 到 `formal-exp2a-gate.md` 执行并签字；完成相机与载荷接口标定后，另行审核正式配置哈希。审核通过前继续禁止正式算法串口运动和论文统计。

## 不应误用的旧代码

仓库中的旧导航、建图和键盘控制包为历史功能，接口仍可能使用 `/cmd_vel` 或 `/agv_chassis/cmd_vel`。它们没有纳入冻结执行链，正式测试时不得与 `multi_agv_bringup` 同时作为控制源。当前底层串口帧格式保持原模式，但 ROS 上层入口已经冻结为每车 `/agvX/chassis_command`，因此不能用旧键盘节点来证明新链路合格。
